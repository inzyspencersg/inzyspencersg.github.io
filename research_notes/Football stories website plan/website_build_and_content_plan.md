## Key Question 1: Tech stack options for GitHub Pages and alternatives

### Takeaway
For a non-coder owner with an AI assistant doing the coding, the strongest option is Astro (Markdown content collections) built by GitHub Actions and deployed to GitHub Pages, with Pages CMS (free, hosted, GitHub-login, no server to run) as the owner's editing UI. Jekyll remains the zero-config native option but is pinned to Jekyll 3.10 with a restricted plugin set; hosted CMSs (Ghost, Substack, WordPress.com, Squarespace, Webflow) trade monthly fees or revenue share for convenience and remove the need for an AI assistant at all.

### Cited Findings

GitHub Pages platform facts
- GitHub Pages is free for public repositories on GitHub Free; private-repo Pages requires a paid plan — [GitHub Docs via search](https://docs.github.com/en/enterprise-server@3.15/pages/setting-up-a-github-pages-site-with-jekyll/about-github-pages-and-jekyll)
- Limits: source repository recommended at or under 1 GB; published site must not exceed 1 GB; 100 GB/month bandwidth soft limit; 10 builds/hour soft limit (does not apply when publishing via a custom GitHub Actions workflow); deployments time out after 10 minutes; rate-limited requests get HTTP 429 — [GitHub Docs: GitHub Pages limits](https://docs.github.com/en/pages/getting-started-with-github-pages/github-pages-limits)
- GitHub's docs say GitHub Actions is now the recommended approach for deploying and automating Pages sites, while the github-pages gem remains supported — [GitHub Docs via search](https://docs.github.com/ja/enterprise-server@3.14/pages/setting-up-a-github-pages-site-with-jekyll/about-github-pages-and-jekyll)
- Custom domains on GitHub Pages are served over HTTPS — [unilink GitHub Pages tutorial 2026](https://www.unilink.us/blog/github-pages-tutorial-2026) (third-party)

Jekyll (native GitHub Pages builder)
- The built-in builder uses Jekyll 3.10.0, github-pages gem v232, kramdown 2.4.0; the dependency page was last updated 30 January 2025 and is also published as JSON at pages.github.com/versions.json — [pages.github.com/versions](https://pages.github.com/versions)
- The native builder only loads a whitelisted set of plugins, which includes jekyll-feed, jekyll-seo-tag and jekyll-sitemap — [Jekyll on GitHub cheatsheet](https://docs.w3cub.com/cheatsheets/jekyll-github); third-party 2026 guide also says the built-in builder is limited to a small set of gems and recommends an Actions workflow for full plugin support — [unilink](https://app.unilink.us/blog/github-pages-tutorial-2026)
- Installing the github-pages gem locally installs Jekyll plus all whitelisted plugins — [Siteleaf docs](https://learn.siteleaf.com/themes/jekyll-plugins)

Astro, Eleventy, Hugo
- 2026 practitioner consensus summarized as "pick Astro, unless you have a specific reason"; Hugo wins raw build speed, Eleventy wins config-light simplicity, Gatsby is in soft decline — [jwatte SSG comparison 2026](https://jwatte.com/blog/blog-ssg-comparison-2026/); [gautamkhorana 2026](https://gautamkhorana.com/blog/static-site-generators-2026-astro-eleventy-hugo-jekyll-gatsby/)
- Astro can mix components and Markdown directly, which Eleventy and Hugo only approximate via shortcodes; one 91,000-page Astro site reports median Lighthouse mobile 92 and ~18 min full rebuild — [jwatte](https://jwatte.com/blog/blog-ssg-comparison-2026/)
- Hugo: Go single binary, Go templates, built-in asset pipeline (Hugo Pipes) — [Hugo forum thread](https://discourse.gohugo.io/t/hugo-vs-astro-vs-nextjs-which-one-is-better-for-content-focused-website/42858); [is-pro.dev comparison](https://is-pro.dev/guides/static-site-generators-comparison/)
- Eleventy described as the choice when "I just want HTML" is the brief; weak spot is interactive components — [jwatte](https://jwatte.com/blog/blog-ssg-comparison-2026/)
- Astro has an official GitHub Pages deploy action (`withastro/action`, currently v6 in docs), configured via `site`/`base` in `astro.config.mjs`; for a custom domain set `site` to the domain and omit `base`; workflow needs `pages: write` and `id-token: write`; commit a lockfile so the action detects the package manager — [Astro docs: Deploy to GitHub Pages](https://v4.docs.astro.build/en/guides/deploy/github/)

Git-based editors (so the owner never touches code)
- Pages CMS: open-source CMS for static sites stored in GitHub repos; no separate content database; configured by a `.pages.yml` file in the repo; edits are saved back to GitHub through a web UI; usable entirely online without installing or deploying anything; commonly used with Astro, Hugo, Jekyll, Next.js — [Pages CMS docs](https://pagescms.org/docs/); [Astro docs: Pages CMS](https://docs.astro.build/de/guides/cms/pages-cms/); [Jamstack.org listing](https://jamstack.org/headless-cms/pages-cms/)
- Decap CMS (ex-Netlify CMS): the GitHub backend needs a server for OAuth; Netlify's auth provider is the built-in route, otherwise you run a community-maintained external OAuth client and set `base_url` — [Decap docs: GitHub backend](https://decapcms.org/docs/github-backend/); [Decap docs: backends overview](https://decapcms.org/docs/backends-overview/); a Cloudflare Pages user described non-Netlify setup as "you're on your own, and the documentation is... imperfect" — [i40west/netlify-cms-cloudflare-pages](https://github.com/i40west/netlify-cms-cloudflare-pages)
- Sveltia CMS is a drop-in Decap replacement built in Svelte; on GitHub Pages it needs a small Cloudflare Worker ("Sveltia CMS Authenticator") for GitHub OAuth, or a personal access token for a sole developer; the authenticator is planned for deprecation once GitHub supports client-side PKCE for SPAs — [dylanbeattie.net: Sveltia, Jekyll and GitHub Pages](https://dylanbeattie.net/2025/02/13/sveltiacms-jekyll-and-github-pages.html); [sveltia-cms-auth fork README](https://github.com/MattBlogsIT/sveltia-cms-auth); [Sveltia discussion on unclear Cloudflare docs](https://github.com/sveltia/sveltia-cms/discussions/218)

Hosted alternatives
- Ghost(Pro): Starter $18/mo monthly ($15/mo annual) with a hard 1,000-member cap, includes website, newsletter and a free custom domain; Publisher $29/mo annual ($35 monthly) and Business $199/mo annual ($239 monthly) scale with audience; 0% revenue share on all plans except Starter — [typeflo Ghost pricing 2026](https://typeflo.io/blog/ghost-pricing-plans); [emailsoftwareinsights](https://www.emailsoftwareinsights.com/reviews/ghost/pricing/) (third-party; one outlier source lists different tiers and was discounted)
- Substack: no software fee; 10% of paid subscription revenue plus Stripe fees (2.9% + $0.30 and a 0.7% recurring-billing fee); custom domain is a one-time $50 connection fee not including the registrar; all-in roughly 13–16% of gross; extra Apple cut on iOS in-app purchases — [ruzuku Substack pricing](https://www.ruzuku.com/learn/articles/substack-pricing); [reallygoodbusinessideas](https://www.reallygoodbusinessideas.com/p/is-substack-free) (third-party)
- Pagefind (static search) is free and open source; it runs in the browser from a chunked index so a 10,000-page site's search can load under 300 KB including the library, closer to 100 KB for most sites — [CloudCannon: Introducing Pagefind](https://cloudcannon.com/blog/introducing-pagefind/); [pagefind.app](https://www.pagefind.app)

### Inferences
- Recommended default: Astro + Markdown/MDX content collections + GitHub Actions deploy + Pages CMS. Rationale: Astro has the richest ecosystem for the storytelling features the owner wants (OG image generation, view transitions, component-level interactivity for timelines) and official GitHub Pages tooling; Pages CMS gives the owner a form-based editor with GitHub login and no OAuth server to maintain, which is the main pain point of Decap/Sveltia on GitHub Pages. The AI assistant writes the `.pages.yml` schema once (title, dek, hero image, club, era, country, tags, reading time auto-computed) and the owner only fills in fields and writes Markdown.
- Jekyll is the right choice only if the owner wants zero GitHub Actions and accepts Jekyll 3.10 plus the plugin whitelist. Because GitHub itself now recommends Actions, there is no practical penalty for Astro/Eleventy/Hugo; the 10 builds/hour soft limit does not even apply to Actions-based deploys.
- Eleventy is the second-best pick if the AI assistant and owner prefer minimal JavaScript tooling; Hugo is only worth it if the archive grows past several thousand stories and build time becomes a felt problem.
- Next.js static export is not recommended: heavier toolchain, no advantage for a content site, and more surface area for a non-coder to break.
- Hosted CMS trade-off: Ghost Starter (~$180/yr) or Substack (free until paid subscriptions) remove the need for an AI assistant and bundle a newsletter, but you lose free hosting, full design control, Markdown-in-git portability and the ability to add custom features (timelines, club index pages, Pagefind). A hybrid is sensible: static site on GitHub Pages as the canonical archive plus a newsletter tool for distribution (see Key Question 4).
- Dependency hygiene matters for a non-coder: pin Astro and action versions; ask the AI assistant to set up Dependabot or Renovate with grouped monthly PRs so updates arrive as reviewable bundles rather than breaking builds silently.

### Gaps
- Could not read the full GitHub Pages docs, Pages CMS docs or any vendor pricing page directly (proxy blocked). Pages CMS's hosting/pricing model (whether the hosted app at pagescms.org has limits or a paid tier) is unverified; sources only say "free and open source".
- No source found on WordPress.com, Squarespace or Webflow 2026 pricing; these were not researched in depth and should be checked if the owner is seriously considering them.

## Key Question 2: Site structure and features proven for storytelling sites

### Takeaway
A storytelling site needs a small number of well-made templates (home feed, story page, index/taxonomy pages, collections/series, about/author, newsletter) plus invisible plumbing (RSS, sitemap, Open Graph, Article JSON-LD, Pagefind search). Everything on this list is achievable on a static site; the few verifiable external requirements (Article schema fields, Pagefind behaviour) are cited below, the rest is editorial best practice marked as inference.

### Cited Findings
- Google's Article structured-data guidance covers Article, NewsArticle and BlogPosting and says it can help Google show better title text, images and date information for news, blog and sports article pages; its example JSON-LD uses `headline`, `image`, `datePublished`, `dateModified`, `author`; `datePublished` is recommended not required; `headline` should be concise; `image` URLs must be crawlable and representative (not logos) — [Google Search Central: Article structured data](https://developers.google.com/search/docs/data-types/article)
- Pagefind indexes a built static site post-build, adds a static search bundle with a JS API and optional prebuilt UI, chunks the index so the browser only loads a subset, and stores result text/metadata separately — [CloudCannon launch post](https://cloudcannon.com/blog/introducing-pagefind/); one user on simulated slow 3G said the bandwidth is noticeable — [waylonwalker thought-112](https://waylonwalker.com/thought-112.md)
- Jekyll's whitelisted jekyll-seo-tag, jekyll-feed and jekyll-sitemap cover meta tags/OG, RSS and sitemap on the native builder — [cheatsheet](https://docs.w3cub.com/cheatsheets/jekyll-github)
- These Football Times (reference model for long-form football publishing): independent UK publication founded 2011, emphasises long-form writing, free online content with paid bi-monthly themed print issues (per country, competition or club), runs interviews, analysis, podcast, pays freelancers, part of the Guardian Sport Network and partners with The Athletic — [Wikipedia: These Football Times](https://en.wikipedia.org/wiki/These_Football_Times); [TFT about](https://thesefootballtimes.co/about-us/); club-commissioned 150-page Valencia issue — [Valencia CF](https://www.valenciacf.com/en-valencia-cf-featured-in-these-football-times-magazine-issue-2021-05-05)
- Astro OG image generation options: `astro-og-canvas` (npm, latest 0.7.0, `OGImageRoute` helper generates `getStaticPaths`/`GET` for a dynamic route; Astro 3.x+ needs 0.2.x+; pnpm users must add `canvaskit-wasm`) or DIY Satori (JSX + CSS subset to SVG) + resvg-js to PNG; OG protocol supports JPEG/PNG only — [npm astro-og-canvas](https://npmjs.com/package/astro-og-canvas); [morellodev on DEV](https://dev.to/morellodev/generating-og-images-at-build-time-with-satori-and-astro-4b4b); one developer found astro-og-canvas "a much nicer fit" than Satori+resvg — [fullmetalbrackets](https://fullmetalbrackets.com/blog/how-to-dynamically-generate-og-images-with-astro)

### Inferences (recommended information architecture; editorial best practice, not externally sourced)
- Content model (front matter the AI assistant should define, and Pages CMS should expose as fields): `title`, `dek` (standfirst), `slug`, `date`, `updated`, `hero` (image path), `heroCredit`, `heroAlt`, `pillar` (one of the content pillars), `clubs[]`, `players[]`, `countries[]`, `eras[]` (decade buckets), `competitions[]`, `tags[]`, `series` (optional collection name + order), `sources[]` (list of citations shown at the foot of every story), `readingTime` (computed at build), `draft` boolean.
- Page types: (1) Home: latest stories feed with one featured "lead" story, a "Story of the day/week" slot driven by a front-matter flag or date rotation, pillar entry points, newsletter box. (2) Story page: hero image + credit, dek, byline/date/reading time, body with pull quotes (a Markdown/MDX component), inline image captions with credits, "Sources" footer, share buttons (plain URL-intent links for X, Facebook, WhatsApp, Threads, copy-link; no third-party scripts), "Related stories" (same club/pillar/era, computed at build), prev/next in series. (3) Taxonomy index pages auto-generated per club, player, country, era, competition, tag, pillar, each with its own OG image. (4) Collections/series landing pages (e.g. "Malaysia Cup years"). (5) Timeline pages: a reusable component rendering a dated list from front matter or a YAML data file (club history, a player's career). (6) About/author page with editorial standards and corrections policy. (7) Archive page (all stories by year). (8) Search (Pagefind UI). (9) RSS feed (full-text), sitemap.xml, robots.txt, 404.
- Plumbing: Open Graph + Twitter card meta on every page; per-story OG image generated at build (astro-og-canvas) using title, dek, pillar colour and site mark; Article JSON-LD with headline, image, datePublished, dateModified, author, publisher; BreadcrumbList JSON-LD on taxonomy pages; canonical URLs; `<link rel="alternate" type="application/rss+xml">`.
- Performance and accessibility defaults: system or two self-hosted fonts, responsive images with width/height set (Astro `<Image>` generates AVIF/WebP), lazy loading below the fold, no third-party JS except analytics, dark mode via `prefers-color-scheme`, skip link, proper heading hierarchy, alt text mandatory in the CMS schema, colour contrast checked. Target: Lighthouse 95+ mobile on story pages.
- Search choice: Pagefind over Lunr. Lunr builds a single JSON index that grows with the site and is loaded whole; Pagefind's chunked WASM index scales better and ships a ready UI. For a site under ~200 stories either works; Pagefind is the lower-maintenance default because it needs no custom indexing code.

### Gaps
- No case-study source on The Athletic's or Longform's feature-page architecture was found; the IA above is practitioner inference rather than a documented case study.
- Google's English Article documentation could not be fetched; the "required vs recommended" status of `image` and `headline` was only confirmed via a translated page and a third-party schema library.

## Key Question 3: Social sharing mechanics

### Takeaway
Generate the share image once at build time (astro-og-canvas or Satori), make the story page the single source of truth, and derive social captions from the dek and pull quotes. Free tiers of Buffer and Metricool cover a solo creator's scheduling needs; Linktree's free tier works for link-in-bio but a self-built `/links` page on the site is better.

### Cited Findings
- OG image generation at build time: Satori (Vercel) converts JSX+CSS subset to SVG, resvg-js rasterises to PNG; astro-og-canvas wraps a similar pipeline for Astro with `OGImageRoute` — [DEV: Satori and Astro](https://dev.to/morellodev/generating-og-images-at-build-time-with-satori-and-astro-4b4b); [npm astro-og-canvas](https://npmjs.com/package/astro-og-canvas)
- Buffer free plan: commonly described as 3 social channels with 10 scheduled posts per channel at a time; analytics and AI assistant reported paid-only by one review, contradicted by CostBench — [marcandrews Buffer free limits 2026](https://marcandrews.com/?p=2565); [CostBench Buffer](https://costbench.com/software/social-media-management/buffer/free-plan) (sources conflict)
- Metricool free plan: third parties say 1 brand, ~20 posts/month, no LinkedIn or X; Metricool's own comparison page claims up to 11 channels and 50 posts/month for $0 — [Metricool vs Buffer (vendor)](https://metricool.com/metricool-vs-buffer/); [socialk.it Metricool pricing](https://socialk.it/en/pricing/metricool); [CostBench Metricool](https://www.costbench.com/software/social-media-management/metricool/free-plan/) (sources conflict; vendor figure is marketing)
- Linktree free plan: $0 forever, unlimited links, QR code, basic themes, Linktree branding, no custom domain, total-visit analytics only, 12% fee on payment blocks; paid tier prices conflict across sources ($5/$9/$24 vs $8/$15/$35 after a reported Nov 2025 price rise) — [replug Linktree pricing](https://replug.io/blog/linktree-pricing); [unilink Is Linktree free](https://www.unilink.us/blog/is-linktree-free)
- Wikimedia Legal on CC BY-SA and social media: attribution placed with the work (same post or via embed) generally keeps reuse within licence; omitting author/licence/source or a broken link falls short — [Wikimedia Legal: CC BY-SA licenses and social media](https://meta.wikimedia.org/wiki/Legal/CC_BY-SA_licenses_and_social_media)

### Inferences
- One-source-many-outputs workflow: the story's front matter already holds title, dek, hero and 2–3 pull quotes. The AI assistant can add a build step that emits, per story, a `social.md` (or a hidden `/share/<slug>` page) containing: an X/Threads thread (hook line, 3–5 facts, link), a Facebook caption (dek + question to prompt comments + link), an Instagram caption (dek, 3–5 hashtags, "link in bio") and alt text. The owner copies and pastes; no API integration is needed and nothing can break.
- Instagram carousels: generate 1080x1350 (4:5) slide images at build with the same Satori/og-canvas pipeline (cover slide = title, 3–6 slides = one pull quote or fact each, last slide = CTA). This is a static-image route that avoids Canva lock-in, but Canva's free tier remains the pragmatic choice for occasional hand-made graphics.
- Link-in-bio: build a `/links` page on the site (latest 5 stories pulled at build, newsletter signup, socials) instead of Linktree; it is free, branded, on the owner's domain and gets analytics from the site's own tool.
- Scheduling: start with Buffer free (3 channels is enough for Instagram, Facebook, Threads or X); move to Metricool if more channels or analytics are needed. Native scheduling in Meta Business Suite is also free for Facebook+Instagram.
- Share buttons on the site should be plain intent links (`https://twitter.com/intent/tweet?...`, `https://www.facebook.com/sharer/sharer.php?u=`, `https://wa.me/?text=`, `https://www.threads.net/intent/post?text=`) plus a copy-link button; no embedded SDKs, for privacy and speed.

- Threads and X intent-URL behaviour in 2026 was not verified.

## Key Question 4: Newsletter options, costs and embedding on a static site

### Takeaway
Newsletter tools fall into three tiers: free-and-simple for a hobbyist (Buttondown free to 100 subscribers, Kit free, beehiiv Launch free to 2,500), platform-with-audience (Substack, free but 10% of any paid revenue), or publishing suite (Ghost). On a static site, embed via the provider's hosted form (HTML snippet or plain `<form action>`), and use RSS-to-email where offered so publishing a story on the site is the only manual step.

### Cited Findings
- beehiiv Launch: $0 up to 2,500 subscribers, unlimited sends, site and custom domain, no email automations; Scale reported at $42–43/mo and Max $84/mo — [superframeworks newsletter platforms 2026](https://superframeworks.com/articles/best-newsletter-platforms-indie-hackers); [saascrmreview](https://saascrmreview.com/best-email-newsletter-tools/) (third-party)
- Buttondown: free for first 100 subscribers; Standard $9/mo; Professional $29/mo; automations sold as an add-on — [superframeworks](https://superframeworks.com/articles/best-newsletter-platforms-indie-hackers) (third-party)
- Kit (ConvertKit): free Newsletter plan with one basic visual automation; one source says free up to 10,000 subscribers (single source); paid Creator reported at $29/mo or $33/mo annual with a reported 35% price rise — [superframeworks](https://superframeworks.com/articles/best-newsletter-platforms-indie-hackers); [mailmodo MailerLite pricing guide](https://www.mailmodo.com/guides/mailerlite-pricing/) (third-party, unconfirmed)
- MailerLite free plan: multiple sources say it was cut in Sept 2025 to 500 subscribers/12,000 emails, then on 1 July 2026 to 250 active subscribers/2,500 emails per month with further automation/form caps from Aug 2026 — [groupmail MailerLite free plan 2026](https://blog.groupmail.io/mailerlite-free-plan-limits/); [mailsoftly](https://mailsoftly.com/blog/mailerlite-free-plan-changes/); [CostBench](https://costbench.com/software/marketing-automation/mailerlite/free-plan/) (third-party)
- Substack: 10% of paid revenue + Stripe fees; $50 one-time custom domain fee — [ruzuku](https://www.ruzuku.com/learn/articles/substack-pricing) (third-party)
- Ghost(Pro) Starter $18/mo ($15 annual) to 1,000 members, bundles website + newsletter + custom domain — [typeflo](https://typeflo.io/blog/ghost-pricing-plans) (third-party)
- Cadence guidance (practitioner sources, not Nieman Lab): weekly is the bare minimum to stay in front of an audience — [Leaky Paywall cadence guide](https://leakypaywall.com/how-often-should-publishers-send-newsletters/); consistency matters more than frequency; only 15.82% of creators publish daily (beehiiv data, 2025); draft three issues before launch; click rate, not open rate, is the reliable metric after Apple Mail Privacy Protection — [bestwriting.com newsletter playbook](https://bestwriting.com/newsletters)
- Singapore Spam Control Act 2007 (in force; amendment tags to 2016/2020 seen): bulk unsolicited commercial electronic messages must honour unsubscribe requests within 10 business days; a recipient is not treated as consenting after that — [Singapore Statutes Online: Spam Control Act](https://sso.agc.gov.sg/Act/SCA2007); PDPA requires telling subscribers the purpose of collection, obtaining consent (express or deemed when voluntarily given), providing a withdrawal route such as an unsubscribe link, and ceasing use after withdrawal — [SingaporeLegalAdvice: email newsletters](https://singaporelegaladvice.com/law-articles/email-newsletters-comply-singapore-law)

### Inferences
- Recommended path for a hobbyist: start on Buttondown (free to 100; Markdown-native; RSS-to-email on paid plans; plain HTML form embed works on a static page) or Kit free (larger free ceiling, embeddable forms, one automation for a welcome email). Move to beehiiv Launch if growth is the priority (2,500 free, referral/recommendation network), accepting that it is a heavier marketing product. Avoid MailerLite because its free tier has been cut twice in 12 months.
- Substack only if the owner wants a built-in discovery network and is willing for Substack, not the GitHub Pages site, to become the primary home; otherwise the static site should stay canonical and the newsletter should link back to it.
- Embedding: use the provider's hosted form via a plain `<form method="post" action="...">` (works without JavaScript, no third-party script, better for performance and privacy) and a thank-you page on the site. Add a footer note: "By subscribing you agree to receive the newsletter; unsubscribe any time" plus a link to a short privacy page; this satisfies the PDPA purpose-notice and consent points cited above.
- Cadence: fortnightly newsletter ("two stories and three links") is realistic for a solo creator; weekly only if the 90-day plan shows the research pace supports it.

- Vendor pricing pages could not be fetched; every price above is from third-party comparisons and should be rechecked. Kit's free-tier subscriber ceiling (reported 10,000) has only one source.
- Whether the 2018 PDPC proposal to merge Do Not Call and Spam Control rules into one Act was ever enacted is unconfirmed; the Spam Control Act 2007 still appears on Singapore Statutes Online.

## Key Question 5: Content pillars (with sourcing difficulty and evergreen value)

### Takeaway
Pillars should mix high-evergreen global formats (cult heroes, forgotten finals, one-club men, kit and stadium histories) with a differentiated Singapore/Southeast Asia strand (Malaysia Cup era, Fandi Ahmad, the Kallang Roar) where the owner has a comparative advantage and NewspaperSG supplies primary sources. Sourcing-difficulty and evergreen ratings below are the researcher's judgment, not cited metrics.

## Key Question 6: Editorial operations for a solo creator

### Takeaway
Sustainable solo cadence is one substantial story per fortnight plus light-weight weekly formats (on-this-day, short profiles), with a research workflow built on free archives (NewspaperSG, Wikimedia, RSSSF/11v11 as indexes), one paid archive if needed (British Newspaper Archive, roughly £80/year list), a written style guide, a sources footer on every story, and clear rules for AI assistance. A 90-day plan should spend the first month on the build and a content buffer, not on publishing.

### Cited Findings
- NewspaperSG: Straits Times digitised from 1845; remote access to SPH titles up to ~1989/1990; later issues on-site only; republication requests for SPH titles go to SPH Media's Information Resource Centre; downloaded articles are watermarked, unwatermarked copies obtained in person at NLB — [NLB FAQ](https://eresources.nlb.gov.sg/newspapers/faq); [NUS LibFAQ](https://libfaq.nus.edu.sg/faq/71323); [Wikipedia](https://en.wikipedia.org/wiki/NewspaperSG)
- British Newspaper Archive: older list price about £80/year; a 2026 deals aggregator lists monthly from £8.34; BNA has been owned by Findmypast (DC Thomson) since 2025; the British Library has also put 1 million newspaper pages online free — [IanVisits](https://www.ianvisits.co.uk/articles/british-library-puts-1-million-newspaper-pages-online-for-free-46394/); [Irish Genealogy News 2020](https://www.irishgenealogynews.com/2020/04/30-off-12-month-sub-to-british.html?m=0); [Savoo (aggregator)](https://www.savoo.co.uk/brands/british-newspaper-archive-promo-codes); [Wikipedia](https://en.wikipedia.org/wiki/British_Newspaper_Archive)
- Transfermarkt data is largely user-generated with editor oversight; errors occur; market values are estimates; academic work (Coates and Parshakov 2020) found crowd-sourced values are biased predictors of actual fees — [Wisdom of Crowds and Transfer Market Values](https://mdsoar.org/items/08e5d64e-ee10-4be4-a8de-1d3982a062c7/full)
- Newsletter/publishing cadence: weekly minimum to stay front of mind; consistency over frequency; draft three issues before launch; clicks not opens — [Leaky Paywall](https://leakypaywall.com/how-often-should-publishers-send-newsletters/); [bestwriting.com](https://bestwriting.com/newsletters)
- Republishing or quoting someone else's defamatory claim is itself publication under Singapore law, even with a disclaimer or in quotation marks — [Thuraisingam: Defamation laws in Singapore](https://thuraisingam.com/news-mentions/defamation-laws-in-singapore-explained/amp) (relevant to fact-checking anecdotes about living people)

### Inferences
- Research workflow: (1) pick subject from the on-this-day calendar or pillar backlog; (2) build a skeleton timeline from Wikipedia + RSSSF/11v11 as indexes only; (3) confirm every date, score and quote against at least one contemporary primary source (NewspaperSG, BNA, club official history, autobiography) and record the citation in `sources[]`; (4) write; (5) run a fact-check pass on names, dates, scores, spellings, nationality and living/deceased status; (6) image sourcing and credits (see KQ7); (7) publish via Pages CMS; (8) derive social outputs.
- Responsible AI use: use the assistant for outlining, finding archive search terms, tightening prose, generating alt text and social variants, and spotting internal inconsistencies; never for facts or quotations without a cited primary source; disclose on the About page that AI tools assist with editing and code, not with factual claims; keep a corrections log page.
- Style guide elements: house spelling (British English, "football"); name conventions (full name first mention, surname after; local naming conventions for Malay and Chinese names); number/score/date formats; how to cite (footer "Sources" list with publication, date, page where known); image credit format ("Photo: Name / Wikimedia Commons, CC BY-SA 4.0"); dek length (under 160 characters so it doubles as meta description); target lengths (1,200–2,000 words long-form; 300–500 words short formats); tone notes; sensitivity rules for deaths, criminal allegations, and living people's private lives.
- Realistic cadence: Month 1 build + 6-story buffer; thereafter 1 long-form story per fortnight, 1 short format per week, 1 newsletter per fortnight, 3–4 social posts per week drawn from the archive. That is roughly 6–8 hours per week.
- 90-day plan: Days 1–14: AI assistant scaffolds Astro site, Pages CMS schema, templates, OG images, Pagefind, RSS, analytics, newsletter form; owner buys domain and writes About/standards page. Days 15–30: owner writes 6 stories (2 per core pillar) and builds a 365-row on-this-day data file for the first quarter; assistant tests mobile performance and accessibility. Days 31–45: soft launch to friends; publish 2 stories/week from the buffer; first newsletter; set up Buffer. Days 46–75: steady state cadence; add first series/collection (e.g. Malaysia Cup years); first NLB on-site archive visit for post-1990 material. Days 76–90: review analytics (which pillars earn reads, time on page, newsletter clicks), prune or promote pillars, write the quarter-two calendar.

- Current BNA 2026 list price unconfirmed; only an aggregator figure found.

## Key Question 7: Images and legal basics

### Takeaway
Use Wikimedia Commons (verify each file page, attribute author + licence + link), Getty's embed tool for editorial-only embeds where it is still offered, own photography, and occasional paid Alamy individual licences (from £17/asset) for must-have images; treat club crests as trademarks (describe, do not brand), quote sparingly under Singapore's open-ended fair use (and UK fair dealing for UK material), and apply a living-persons rule because both Singapore and UK defamation law treat repeating an allegation as publishing it.

### Cited Findings
Images
- Wikimedia Commons reuse: verify each file's copyright status yourself (the Foundation gives no warranty); for CC BY/CC BY-SA, attribution must accompany the work with author, licence and source link; "from Wikimedia Commons" alone is insufficient; modified ShareAlike works must carry a compatible licence; non-copyright restrictions (trademarks, personality rights, privacy, moral rights) still apply and vary by jurisdiction — [Commons: Reusing content outside Wikimedia](https://c.enwp.org/wiki/Commons:REUSE); [Wikimedia Legal: CC BY-SA and social media](https://meta.wikimedia.org/wiki/Legal/CC_BY-SA_licenses_and_social_media)
- Getty embed tool (terms as reported at 2014 launch; current terms not retrieved): free for non-commercial, editorial-only use with attribution and link back; no advertising/promotion/merchandising or implied endorsement; a Getty spokesperson said ad-supported sites were fine as long as images do not promote a product or business; Getty reserves the right to monetise the viewer and can remove content remotely — [Computerworld 2014](https://www.computerworld.com/article/1383852/getty-makes-35-million-images-embeddable-to-gather-data-monetize-usage.html); [Econsultancy](https://econsultancy.com/five-key-implications-of-getty-images-embeds-that-publishers-need-to-know/); [PetaPixel](https://petapixel.com/2014/03/06/thoughts-gettys-embed-tool/)
- Alamy: Individual licence for people working alone, single use across websites and social media (including short-form video), from £17.00 per asset, non-transferable; some images restricted to editorial use (shown in a blue box above pricing); separate Live News/Sport sales line — [Alamy licensing and pricing](https://www.alamy.com/help/licensing-and-pricing); [Alamy editorial](https://www.alamy.com/editorial); a third-party listing cites ready-made Personal use $19.99 and Website $49.99 (possibly outdated) — [fitgap](https://us.fitgap.com/products/alamy)
- IMAGO: RM licences for one-off use, RF Classic for recurring; webshop sells single licences or credit packages (credits valid 365 days); volume pricing via sales managers; no public price list found — [IMAGO blog: licensing sports images](https://blog.imago-images.com/en/licensing-the-best-photos-of-womens-soccer-players-a-comprehensive-practical-guide-for-blogs-news-and-social-media); a different agency (East News) lists online sport image prices of roughly 30–90 EUR by use, indicative only — [East News price example](https://eastnews.pl/en/picture/115573613?top=1)
- NewspaperSG republication of SPH articles must be cleared with SPH Media's Information Resource Centre; downloads are watermarked — [NLB FAQ](https://eresources.nlb.gov.sg/newspapers/faq); [NUS LibFAQ](https://libfaq.nus.edu.sg/faq/71323)

Crests and trademarks
- Club crests are registered trademarks; in Arsenal v Reed the European Court held Arsenal could protect its mark against a street trader's "badge of allegiance" argument; Manchester United sued Sega over Football Manager's use of the club name/crest (settled; Sega said it did not need a licence for the name) and the dispute highlighted fan-run sites hosting downloadable logos; Peterborough United publishes a brand-use policy — [CITMA: Football clubs and trade marks](https://citma.shorthandstories.com/multi-issue-magazine-fashion/with-our-blogs/football-clubs-and-trade-marks-badge-of-origin-or-mark-of-allegiance/index.html); [World IP Review](https://www.worldipreview.com/news/judge-rejects-man-utd-s-football-manager-fan-site-claims-19746); [Sports.Legal: club badges](https://www.sports.legal/2017/02/football-club-badges-the-legal-implications-of-misuse/); [Peterborough United brand page](https://www.theposh.com/club/club-information/our-brand)

Quoting
- Singapore Copyright Act 2021 replaced fair dealing with an open-ended fair use exception modelled on US 17 USC 107, using four factors (purpose and character, nature of work, amount used, market effect) and dropping the old fifth factor on availability at an ordinary commercial price — [Law Gazette: Key features of the Copyright Act 2021](https://lawgazette.com.sg/?p=10621); [infojustice](https://infojustice.org/?p=43799); a university guide illustrates "reasonable portion" as one chapter or ~10% of a book for study, which is illustrative not a safe harbour — [NYP student handbook](https://mynypportal.nyp.edu.sg/en/student-handbook/shb-academic-matters/shb-copyright-act.html)

Defamation
- Singapore: criminal defamation under Penal Code s.499 and civil defamation under the Defamation Act; truth published for the public good is a defence; sharing or republishing someone else's statement is itself publication, including quotations and even with disclaimers; distributors can be sued; politicians have the same reputation rights as anyone — [Thuraisingam](https://thuraisingam.com/news-mentions/defamation-laws-in-singapore-explained/amp); [PKWA Law](https://pkwalaw.com/?p=9845); [Kelly Warner](https://kellywarnerlaw.com/singapore-defamation-laws)
- UK (relevant for UK clubs/players and UK readers): Defamation Act 2013 s.1 requires serious harm to reputation (serious financial loss for trading bodies), the Supreme Court in 2019 confirmed this raised the threshold; s.2 truth replaces justification; s.3 honest opinion requires a statement of opinion that indicates its basis and that an honest person could have held on facts existing at publication — [legislation.gov.uk: Defamation Act 2013](https://www.legislation.gov.uk/ukpga/2013/26/enacted); [Pinsent Masons defamation guide](https://www.pinsentmasons.com/out-law/guides/defamation-guide)

Newsletter data (Singapore)
- PDPA: state purpose, obtain consent (express or deemed where data is volunteered), provide unsubscribe/withdrawal, stop on withdrawal; Spam Control Act: honour unsubscribe within 10 business days — [SingaporeLegalAdvice](https://singaporelegaladvice.com/law-articles/email-newsletters-comply-singapore-law); [SSO: Spam Control Act](https://sso.agc.gov.sg/Act/SCA2007)

### Inferences
- Image policy for the site: (1) default to Wikimedia Commons with a credit line generated from front matter (`heroCredit`) and a link to the file page; (2) favour stadiums, trophies, programmes, newspaper-era scans in the public domain, and street/landscape shots over close-ups of living players, reducing personality-rights exposure; (3) use Getty embeds only inline (not as hero/OG images, since embeds cannot be used as header images and OG images need a hosted PNG) and only if current Getty terms still permit it; (4) budget a handful of Alamy individual licences per year for flagship stories; (5) own photography of Singapore grounds (Jalan Besar, the new National Stadium, Bishan) is free, differentiated and risk-free; (6) commission or self-make simple illustrations (kit outlines, maps, timelines) to avoid trademark-heavy imagery.
- Crests: do not display club crests as design elements, in OG images or in a "clubs" index grid; name the club in text and use colour swatches or an illustrated kit silhouette instead. Incidental appearance of a crest inside a licensed editorial photograph is normal editorial use.
- Quoting: short attributed quotations from books and articles for comment and criticism, with a sources footer, sit comfortably within Singapore fair use and UK fair dealing for criticism/review; do not reproduce whole newspaper articles or NewspaperSG scans without SPH clearance.
- Living-persons rule: for any allegation about a living person (doping, match-fixing, affairs, financial misconduct), require a reputable published primary source that itself reports an established fact (conviction, official finding, the person's own admission), phrase as reported fact with attribution, and prefer to omit if the story does not need it. Opinion should be clearly framed as opinion with its factual basis stated (this mirrors the UK honest-opinion conditions and the Singapore truth/public-good defence).
- Hosting jurisdiction: GitHub Pages is US-hosted; there is no Singapore data-residency requirement for a hobby publication, but the newsletter list is personal data under the PDPA regardless of where the provider stores it, so pick a provider with a clear privacy policy and keep a one-paragraph privacy page on the site.

## Key Question 8: Analytics and measurement

### Takeaway
Use a privacy-friendly, cookieless tool so no consent banner is needed: Umami Cloud's free Hobby tier (reported 100K events/month) or GoatCounter (free for non-commercial) cost nothing; Plausible is the polished paid option at about EUR 9/month. Measure reads, read-depth, referrers, newsletter clicks and top pillars rather than raw pageviews.

### Inferences
- Recommendation: Umami Cloud Hobby (free, cookieless, custom events) or GoatCounter (simplest, free non-commercial). Skip GA4: it requires consent banners in many jurisdictions, is heavy, and is overkill for a storytelling site. Upgrade to Plausible only if the owner values its UI and is happy to pay.
- Metrics that matter for a storytelling site: unique readers per story in first 7 days and at 90 days (evergreen tail); scroll depth / read completion (fire a custom event at 25/50/75/100%); referrers by story (search vs social vs newsletter); newsletter signups per 1,000 readers and click-through from each issue; search impressions and queries via Google Search Console (free; verify the domain); top pillars and clubs by cumulative reads to steer the calendar.
